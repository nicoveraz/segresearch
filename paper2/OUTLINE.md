## Abstract (draft, ~150 words)

Byte-level language models such as BLT allocate compute by starting a new patch where a small model's next-byte
entropy is high. We previously showed this rule rarely starts patches at in-line computed results. Here we propose
**novelty patching**: start a patch where the upcoming bytes are unlikely to repeat recent context, estimated by a
2-byte lookup table fitted in seconds on raw text, with no labels, no reference model and no losses. On math, at
equal patch budget, novelty raises computed-result accuracy from 12% to 57% and final-answer accuracy from 61% to
90% at 50M parameters (3 seeds); the gap is absent at 1M and grows with scale; fitting the table on the raw pretraining
corpus keeps the gain. On prose it lowers bits per byte; on code it ties entropy. Analysis shows novelty works where
new content coincides with structural boundaries, which a learned chunker (H-Net) finds on its own. We release code
and a preregistered scale-up plan.

## 1. Introduction
- BLT's entropy patching; the blind spot (paper 1): computed results are predictable-looking to a small model but
  need fresh compute.
- Question: is there a cheap, label-free rule that puts boundaries where they matter?
- Idea (compression view): an LZ77-style compressor encodes text as copies of earlier substrings plus new
  literals; copies are cheap, new content is where information enters. Boundaries belong where the compressor
  would stop copying.
- Contributions:
  1. Novelty patching: a self-supervised 2-byte table, fitted in seconds (Section 3).
  2. Math results across 1M / 12M / 50M, 3 seeds each; gain grows with scale; corpus-fitted version (Section 4).
  3. Scope beyond math: prose (win), code (tie) (Section 5).
  4. Why it works: novelty aligns with structural boundaries in math but not in code; H-Net learns such boundaries
     end to end (Section 6).
  5. Negative results that bound the claim: typed uncertainty as a training rule; switching rules at inference;
     learned predictors of novelty and of boundary gain (Section 7).

## 2. Background and related work
- BLT (Pagnoni et al.), entropy and monotonic patchers; MegaByte; SpaceByte; H-Net (Hwang, Wang, Gu 2025);
  "Disentangling language modeling and boundaries" (arXiv 2608.03599).
- Paper 1: the blind spot, dependence table (loss-learned), BLT-1B window fix (transformers #49185).
- Compression view: LZ77 (Ziv and Lempel 1977) and its parsing into copies and literals; compression as
  prediction / MDL; compression-based segmentation (e.g. LZ phrase boundaries as segment cues).
- Adaptive computation / early exit (confidence-based), for the contrast "uncertain vs new".

## 3. Method
- Novelty target: minus the forward LZ match length of the upcoming bytes within the last 128 (cap 16).
- Predictor: mean target per preceding 2-byte context (fallback 1 byte, global mean); threshold = top R% on train.
  Causal: depends only on bytes before t.
- Two fits: nov (GSM8K/MATH solution text) and novc (4M bytes of the raw training corpus, no math-specific data).
- Budget matching: train rate vs eval rate (nov10 11.9% eval; novc13 11.4%; entropy10 11.2%). Report both.
- Cost: fitting seconds on CPU; inference is a table lookup (cheaper than entropy's small LM).

## 5. Beyond math (12M, bits per byte; 2 seeds)
- Prose (WikiText-103): novelty 1.770 vs entropy 1.832; every seed separates.
- Code (installed Python): entropy curve 5.9% 1.711, 7.6% 1.650, 9.5% 1.607, 11.7% 1.566; novelty 7.7% 1.684,
  13.1% 1.541 (tie with the extrapolated curve). Equal training budget: novelty wins; equal inference budget: tie or
  slightly worse.
- Code accuracy (12M, equal eval rate, 2 seeds; exact match of whole tokens): copied identifiers 24.3 vs 24.1,
  new identifiers 15.0 vs 15.8 (+0.9 ± 0.1), new numbers 14.2 vs 13.4, copied values after = / return / ( 21.4 vs
  19.6 (-1.8 ± 0.5), new values 16.0 vs 15.7 (entropy vs novelty). A tie with a small trade-off: no hidden win.
- Figure 2: bpb vs eval patch rate on code (entropy curve + novelty points).

## 6. Why it works: novelty and structure
- novstruct / learned_boundary: in math, novelty covers 75% of line starts (chance 1%) and the start of solutions
  ("word?" contexts); in code 0% of statement starts, 57% of its boundaries mid-identifier (hex/escape literals).
- Even the true novelty target covers only 18% of statement starts in code: new ≠ structural in code.
  A 128-byte network predicts the target better (rank corr 0.52 vs 0.39) without fixing this.
- H-Net (public checkpoints): stage-1 chunks start at 45% of statement starts and 35% of right-hand sides at a 26%
  rate, 4% inside identifiers; in math no blind spot (paper-1 follow-up). End-to-end learned chunking recovers
  structure; novelty is a cheap proxy that coincides with it in math.
- Boundary enrichment (SOMBRERO's B; results/enrichment.json): entropy B 1.61 but 1% of computed starts and 12.1%
  computed at 50M; novelty B 1.13 / corpus-fitted 1.03 (near chance) with 99-100% coverage and 57% computed.
  Computed-result starts have average surprisal (3.34 vs 3.12 bits): surprisal-seeking boundaries cannot find them.
  High enrichment predicts the worst computed accuracy (table + one sentence vs SOMBRERO/ByteFlow).
- Framing: the blind spot is about uncertainty-driven allocation; structure-driven boundaries fix it; novelty is
  the label-free, near-zero-cost approximation where structure and novelty coincide.

## 7. What did not work (bounding the claim)
- Typed uncertainty (sure of the kind, unsure of the value) as a training rule: fails at 1M/12M/50M (12M: -27.7 final
  vs entropy); the answer cue does not rescue it.
- Typed at inference on BLT-1B: doubles computed (19.0 → 48.7 at 10%) but collapses final answers (51.4 → 32.0);
  + answer cue: 48.4 / 64.6. Novelty on BLT-1B at inference: 56.5 / 19.4; + answer cue 54.8 / 65.6 (best
  label-free layout without retraining).
- Switching rules at inference without retraining: 12M novelty-trained model collapses (final 73.6 → 0).
- Learned predictors: 8-byte gain network (paper 1 #19) below the table on accuracy; 128-byte gain network too noisy
  at small reference size (inconclusive).
- Combining novelty with entropy (entnov): worse than either (1M).

## 8. Limitations
- Scale: ≤ 50M trained from scratch; BLT-1B only at inference. Preregistered Study A (150M, 12 runs) and Study B
  (BLT-1B full fine-tune) are designed and costed, pending compute.
- Math-centred evaluation; outside math only bpb (plus code accuracy if it lands).
- Fixed 128-byte lookback and 2-byte table; code shows the limit.
- Single architecture family (BLT-lite); final answers need a format cue at inference on BLT-1B.

## 9. Conclusion
- One-paragraph: allocate byte-level compute to new content, not uncertain content; cheap, label-free, scales in math;
  structure is the deeper target.
